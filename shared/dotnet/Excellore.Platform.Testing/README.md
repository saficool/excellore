# Excellore.Platform.Testing

Use `RlsDatabaseChecks` from each service's PostgreSQL isolation tests. Open the connection with that service's restricted `<app>_app` credentials, then assert `GetRuntimeRoleStatusAsync(...).IsSafe` and an empty result from `FindUnprotectedTenantTablesAsync`. Pass the reviewed entries from `infra/db/rls-exempt.txt` through `ParseExemptions`; do not add an exemption in a test alone.

The checks inspect every visible `public` table with a `tenant_id` column for both enabled and forced RLS, and verify that the runtime role is neither a superuser, a `BYPASSRLS` role, nor an owner of a public table (including ownership inherited through role membership). The service's test fixture must also exercise its class T tables with two tenants and the real runtime role. The platform test suite contains a working Testcontainers PostgreSQL example covering no context, cross-tenant reads and writes, transaction-local context reset, and a deliberately unprotected table.

Run `dotnet test Excellore.sln` with Docker available. The integration test uses a disposable PostgreSQL 16.12 container and generated credentials.

`TenantApiIsolationChecks.VerifyAsync(openApiJson, probes)` verifies that every OpenAPI operation under a `{tenantId}` path carries `x-excellore-tenant-scoped: true` and has exactly one test probe. A probe uses the service test host's real `HttpClient` to send requests for the handbook's fixture users and tenants. The harness checks non-members, a tenant mismatch, unknown and suspended tenants, removed members, foreign resource IDs, and missing permission. It also requires a successful authorized request so an always-deny route cannot pass. Set `HasResourceReference: false` only for a route with no resource ID or reference in its path or body; the helper forbids this when the path has another parameter. Set `RequiresPermission: false` only for a deliberate `AllowAnyMember` route. The probe must construct fresh requests for each scenario, including the T1 resource ID inside T2 requests for both U2 and U12, and an authorized T1 request that confirms the resource exists. It returns the HTTP response without reading its body; the harness disposes the response and reports only method, route template, scenario, and status. Run it against disposable service data and a generated OpenAPI document after mapping routes.
